# Failed-draw NGG input probe

`ngg_capture_probe` executes a **compile-only** workgroup/export SPIR-V module against the small buffer inputs retained for one failed draw. It does not rasterize, infer the guest merged-stage ABI, or verify a presented frame. It refuses a capture without the exact buffer blobs; the normal metadata-only failure record is insufficient.

Capture with `PROSPER_CAPTURE_FAILED_INPUTS_PROGRAM=0xPROGRAM`. The ordered executor calls the snapshot helper while handling the failed operation. Full-submit capture reconstructs draws in the capture callback and logs `capture-time`; those bytes are not proven to be the earlier draw-time contents. The snapshot helper has direct tests; an integration test has not yet checked the exact timing of either call site. Each stage snapshot is bounded to 4 KiB per buffer and 64 KiB in total, and an incomplete set is declined rather than partly serialized.

For launch-state provenance, set `PROSPER_NGG_LAUNCH_STATE_PROGRAM=0xPROGRAM` on a live run. Optional `PROSPER_NGG_LAUNCH_STATE_EXTENT=N` matches an `N×N` color target, `PROSPER_NGG_LAUNCH_STATE_INSTANCES=N` matches the instance count, and `PROSPER_NGG_LAUNCH_STATE_TARGET=0xADDR` matches the exact color target. The logger announces its filters and prints at most eight matching draw snapshots at realization. A program-only selector can fill that cap on earlier draws using the same shader, so use the shape filters when tracing a later producer. The `present` mask marks which listed raw registers were programmed in this draw snapshot, in order: GS RSRC1/RSRC2, onchip, ESGS item size, GE_CNTL, NGG subgroup, shader stages, primitive type, GS instance count, GS max vertex output. An absent bit does **not** mean the hardware value was zero. `topo` is the resolved raw guest primitive type; the replay summary separately names its Vulkan topology. Malformed selectors disable the witness with an explicit error.

Compile the selected failed vertex chain using `gpu_replay --retry-failed-chain N --probe-ngg-workgroup-s3 VALUE --retry-failed-chain-spv module.spv capture.prgcap`. `VALUE` is deliberately explicit: #2072 records an unresolved merged-wave-info ABI disagreement. Validate with `spirv-val --target-env vulkan1.3 module.spv`, then run:

```text
ngg_capture_probe capture.prgcap N module.spv outputs.bin
ngg_capture_probe capture.prgcap N module.spv zeroed.bin --zero-inputs
ngg_capture_probe capture.prgcap N module.spv one-muted.bin --zero-binding=4
```

To test a proposed merged-GS launch layout, add `--probe-ngg-packed-offsets` to the `gpu_replay` compile command. Supply `ngg_capture_probe` with `--packed-offsets=FILE`, where `FILE` contains exactly two little-endian `uint32_t` words per flattened lane, interleaved as initial VGPR0 then VGPR1. The compiler still derives the synthetic ES vertex/instance indices from the captured draw count; the file changes only the initial GS offset words. The option is compile-only and intentionally does not choose a layout or admit a live draw. A proposed layout needs a discriminating wrong-layout control and evidence for the guest ES/GS wave partition before its results can be interpreted as guest output. Pair the module and input file explicitly: the probe does not embed a layout signature in SPIR-V.

`gpu_replay --retry-failed-chain N --probe-ngg-full-four-wave --retry-failed-chain-spv module.spv capture.prgcap` **compiles** a portable 256-invocation module that expects ten raw input words per lane: initial v0..v8 followed by wave-uniform s3. It does not infer register values or prove the guest's ES/GS partition. The old captured-input runner continues to refuse this module: a guest-wave reduction using its own workgroup barriers is not safe merely because the module compiles.

Adding `--probe-ngg-native-wave64` to that compile command selects a separate diagnostic module. It uses native subgroup operations for each of four guest Wave64s and refuses guest streams whose workgroup barriers cannot be split into proved phases. The module carries an exact-Wave64 probe marker. On a Vulkan 1.3 device that supports subgroup-size control, full compute subgroups, and 64-lane compute subgroups, `ngg_capture_probe capture.prgcap N native64.spv output.bin --full-inputs=launch.bin` requests exactly four complete 64-lane subgroups in one 256-invocation workgroup. The launch file must contain exactly 256 records of ten little-endian `uint32_t` words; each 64-lane wave must have one identical s3 word. The runner rejects a missing marker, a different workgroup size, an unsupported device, or a nonuniform s3. This is an **offline diagnostic execution**, not live shader admission, a guest launch ABI, or a picture. A Wave32-only device must decline it. Derive input records from guest launch evidence and run a wrong-partition control before interpreting any Kena output.

The output contains 13 little-endian `uint32_t` words per flattened input lane: PRIM, POS0.xyzw, POS1.xyzw, PARAM0.xyzw. A traced module appends two more words. The printed nonzero PRIM count is a raw slot census, not a valid rendered primitive count. The additional indexed-export census decodes each non-null PRIM's three 10-bit vertex indices, checks them against the output buffer, and reads POS1.z from the **referenced vertex slots**. It reports referenced vertices, same-layer candidate primitives, distinct candidate layers, and malformed records separately. It cannot validate a hardware launch, rasterization, layer-routing register state, or the sampled 3D image. On Kena, inspecting POS1.z only on PRIM-carrying lanes missed most exported vertices and made a 16-layer candidate look like six layers.

A changed output under a muted binding proves that the compile-only module reads that input; an unchanged output cannot prove the input is unused in the actual guest draw. The tool currently accepts the five small, dword-aligned bindings used by the selected producer: ConstantBuffer at 2/5/6, VertexBuffer at 3/4. It refuses other layouts or resource classes.

For a native Wave64 module, add `--probe-ngg-trace=PC:VGPR` to the `gpu_replay` command to record one raw VGPR value immediately after a selected **ordinary ALU** instruction. `PC` is the linked program's dword offset. Special dispatcher events such as bounded DPP, barriers, and exports are not traceable PCs; they decline with `no-ordinary-alu-milestone`. The runner detects the trace marker and writes **15** words per lane: the same 13 export words, then the selected value at word 13 and an execution hit (0 or 1) at word 14. A zero value with hit 1 differs from a lane that did not execute the selected instruction. For an EXEC-changing ALU, the hit uses the instruction's entry EXEC and the VGPR value is read after lowering. A loop records the last visit; an unsupported PC or a VGPR not defined there rejects compilation instead of returning a plausible all-zero trace. This remains a diagnostic of the supplied launch file, not evidence that its ES/GS partition matches hardware. Older trace modules without the hit word are refused by the current runner.

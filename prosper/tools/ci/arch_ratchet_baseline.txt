# Baseline for tools/ci/check_arch_ratchet.py -- eleven cross-title and structural costs
# that may go DOWN, never UP.
#
# One row per finding: `RULE|path[|token] VALUE  # optional note`. No line numbers in the key, so
# ordinary code motion never re-keys a row. Rules and their roots are in the checker's docstring.
#
# Two modes. DELTA mode (`--base REF`, what CI and the agent hook run) looks only at files changed
# since the merge base and fails only when THIS change raised a count past its row -- so a stale
# row somewhere else never blocks an unrelated change. FULL mode (no `--base`) checks the whole
# tree against every row; it is the baseline-maintenance report, and it FAILS on:
#   new       a key missing from this file        -> remove the new instance (see the hint printed)
#   increase   a count above its row               -> same
#   decrease   a count below its row               -> lower the row (`--update` does it for you)
#   stale      a row that no longer reproduces     -> delete the row (`--update` does it for you)
# `--update` only ever lowers or deletes rows. Raising or adding one is a hand edit with a
# `# note` saying why, so the reviewer sees it -- for blocking-sync, the note names the
# guest-visible result the new wait or ALL_COMMANDS barrier delivers.
#
# title-dir and file-size VALUES ARE LINE CAPS: growth past the cap fails, and a shrink reports
# `decrease` only once it is more than 2% below the cap, so ordinary edits to a large file do not
# rewrite its row (and do not conflict with every other lane editing that file).
#
# Seeded on main 3247d3a5 by `--emit-baseline`, with no violation fixed: this records the tree as
# it was, not as anyone wants it to be. Refreshed on main 832f3aa6, where #4173 had grown two
# capped files before the gate existed; those two rows carry a note naming it.
#
